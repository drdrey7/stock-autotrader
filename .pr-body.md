## Summary

Add a production-grade **live 200-week SMA** to the Screener: a historical
layer (Alpha Vantage weekly prices + split history) bootstrapped by a new
VPS tool (`apps/history-ingestor`), precomputed `technical_metrics` basis,
and the live 199-completed-weeks + current-quote calculation in the Worker,
extending `/api/screener` without breaking existing consumers.

```
Alpha Vantage (TIME_SERIES_WEEKLY + SPLITS, free tier, 2 keys x 25 req/day)
   -> apps/history-ingestor (VPS, resumable, per-key budgeted, idempotent)
   -> D1 weekly_prices (raw OHLCV + split_adjustment_factor + split_adjusted_close)
   -> D1 technical_metrics (precomputed 199-week basis, 50 rows)
   -> Worker /api/screener = technical_metrics + latest_quotes.price  (live SMA)
```

## Scope (PR2 only)

Weekly history, Alpha Vantage splits, split-only adjustment, D1 storage,
200-week SMA basis, live SMA via the existing Finnhub WebSocket quote,
distance, Screener columns/filters/sorting, bootstrap/resume tooling, weekly
maintenance tooling, tests, docs. **No** daily/minute candles, no RSI/EMA,
no alerts, no Alpha Vantage realtime, no UI redesign, no second universe.

## Alpha Vantage provider

- `TIME_SERIES_WEEKLY?symbol=X&outputsize=full` — ~20y of weekly buckets,
  keyed by the week's last trading day (Thursday on holiday Fridays),
  newest = in-progress week (dropped).
- `SPLITS?symbol=X` — `{symbol, data:[{effective_date, split_factor}]}`.
- Rate behaviour (verified live 2026-08-19): free tier = **25 req/day/key**;
  a soft pacing payload (`Information`) resolves with ~13 s/key pacing; daily
  exhaustion returns `Note` (hard stop). Two independently-obtained keys each
  carry their own 25/day quota. The tool NEVER rotates keys to bypass a
  per-key quota — it stops when every key is exhausted and resumes the next
  day from its checkpoint.

## Secrets

- Both Alpha Vantage keys were discovered in the Hermes private Vault

## Weekly raw data + split-only adjustment

- `weekly_prices` stores raw as-traded OHLCV + `volume` plus
  `split_adjustment_factor` (the cumulative divisor F(t) = product of all
  split ratios effective strictly after that week's end) and
  `split_adjusted_close = raw_close / F(t)`. Example: 400 → 4:1 → 100.
- Split factors use exact `fractions.Fraction` arithmetic end-to-end; floats
  only at the final persistence/display step. Robust for 2:1, 3:1, 4:1, 10:1,
  fractional 3:2 and reverse splits (verified with real NVDA/AAPL fixtures).
- NOT dividend-adjusted — the SMA matches a normal split-adjusted stock chart.

## Live 199 + current calculation & quote-week anchoring

```
SMA200W live = (sum of the 199 completed split-adjusted closes immediately
                preceding the quote's trading week + latest quote price) / 200
```

- The 199-week basis is anchored to the **quote's own trading week** (ISO
  week of `latest_quotes.provider_timestamp` in America/New_York), never to
  wall-clock "today" — correct in market hours, post-close, weekend, Monday
  pre-open, holidays, early-close days; the current week is never
  double-counted.
- `technical_metrics` stores `sum_199` (199 closes ending at anchor week L),
  `anchor_close` (L's close). At read time: quote week == L →
  `(closed_sma_200w * 200 - anchor_close + price)/200` (true 200-week basis —
  the naive `sum_199 - anchor_close + price` would only supply 198 prior closes
  + the quote = 199 observations, which is wrong); quote week == L+1 →
  `(sum_199 + price)/200`; anything else → honest `Unavailable`.
- Distance = `(price / sma200w − 1) × 100` raw; state on the raw value:
  `< 0 Below`, `0..3 Near`, `> 3 Above` (exactly +3.00 is Near; the boundary
  uses a float epsilon so an exact 3.00 never flips due to IEEE754).
- Fewer than 199 completed weeks → `NotEnoughHistory` (no manufactured
  values); no quote or no basis → `Unavailable`.

destructive migration).

## Bootstrap / resume

`python3 -m history_ingestor bootstrap` — one-shot resumable: loads the
canonical Core Universe (only `core-universe.v1.json`), SPLITS before WEEKLY
per symbol, idempotent UPSERTs, checkpoint after every symbol
(D1 `app_meta.historyBootstrapState` + local mirror), per-key request
accounting with day rollover (resumes across days, no duplicate downloads),
`--dry-run`/`--limit`/`--symbols` flags. Bootstrap requires
50×WEEKLY + 50×SPLITS = 100 requests; under free-tier quota it completes as
much as legitimately allowed each day. **Bootstrap status: see "Bootstrap"
section below.**

## Weekly maintenance

`python3 -m history_ingestor maintenance` — refreshes weekly data, reconciles
split history (a new/changed split rewrites all affected rows, never mixing
adjustment regimes), recomputes `technical_metrics`, verifies coverage
(row counts, ISO-week sequence gaps, <199 weeks) and reports anomalies to
`app_meta.historyMaintenanceReport`. Recurring schedule is documented and
shipped as `deploy/history-ingestor-maintenance.{service,timer}` +
`install-history-ingestor-root.sh` (root install, intentionally not
auto-executed from the repo — same posture as quote-ingestor, and this PR
stops at code + docs + manual run).

**All / Gainers / Losers / Above 200W / Near 200W / Below 200W**, and a

and Gainers/Losers remain. Mobile stays usable (existing horizontal scroll
container; toolbar wraps). The quote-refresh copy is untouched.

## API contract

`/api/screener` rows gain `sma200w`, `distanceToSma200wPct`, `sma200wState`
(`Above | Near | Below | NotEnoughHistory | Unavailable`),
`sma200wHistoryWeeks`, `sma200wAsOf` — `null`/state when not computable. The
old contract remains valid (zod contract tests). One small `technical_metrics`
read (50 rows) per request — **no** 200×50 weekly_prices reads.
